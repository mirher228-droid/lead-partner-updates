# Lead-Partner — обновления общей версии

Публичный канал выпусков общей версии Lead-Partner для сотрудников.

## Сотруднику: установить один раз

1. Откройте [последний выпуск](https://github.com/mirher228-droid/lead-partner-updates/releases/latest).
2. Скачайте `Lead-Partner-Common-AutoUpdate-Setup.zip` и полностью распакуйте его.
3. Запустите `Install-AutoUpdate.bat` и выберите **прежнюю папку Lead-Partner-Common**, уже загруженную в браузере.
4. Дальше Windows проверяет обновления при входе и каждые 15 минут. Скачивание выполняется в отдельную папку.
5. На очередной проверке, если Chrome, Яндекс Браузер и Edge полностью закрыты, обновлятор заменяет файлы. После применения при следующем запуске браузера используется новая версия. Обновлятор не закрывает браузер и не прерывает сохранение заявки.

Если браузер оставляет фоновые процессы после закрытия окна, завершите его через пункт «Выход». До полного завершения процессов обновление будет ждать.

Папка расширения и его ID остаются прежними. Профили браузера, заявки и данные пользователей обновлятор не копирует. Прежняя локальная настройка источников и ключ расширения сохраняются; при ошибке записи выполняется откат к сохранённой копии кода.

## Владельцу: опубликовать обновление

1. Подготовьте ZIP **общей версии**. Внутри должна находиться папка `Lead-Partner-Common` с `manifest.json` и `ROOTRELEASE_FILES.json`.
2. Откройте **Releases → Draft a new release** («Выпуски → Создать выпуск»).
3. Создайте тег `common-v1.2.31`, если в `manifest.json` указана версия `1.2.31`.
4. Приложите файл `Lead-Partner-Common-1.2.31.zip`.
5. Опубликуйте обычный выпуск, отметив его последним. Не включайте «Предварительный выпуск».
6. Дождитесь успешной проверки **Actions → Validate and publish Common updates**. Она проверит архив, добавит `update.json` и установщик автообновления к этому выпуску.

У сотрудников, один раз установивших обновлятор, новая версия загрузится при очередной проверке и применится после выхода из браузера. Создание репозитория само по себе не подключает уже установленные папки на чужих ПК: первоначальный установщик нужен каждому сотруднику один раз.

При ошибке проверки выпуск не получает файл канала обновления. Текущая версия у сотрудников продолжает работать. Исправьте ZIP и повторно запустите проверку через **Actions → Validate and publish Common updates → Run workflow**, указав тег выпуска.

## Проверка и отключение

Локальная папка обновлятора: `%LOCALAPPDATA%\LeadPartnerUpdater\Common`.

Там находятся `status.json` (последний результат), `updater.log` (журнал), загруженный выпуск и резервная копия кода. Для отключения запустите `Uninstall-AutoUpdate.bat` из комплекта: расширение и его настройки остаются на месте.

## Что публикуется

Только общий выпуск, установщик, исходники обновлятора и его проверки. Личные версии Admin и Захара сюда не публикуются. Обновлятор скачивает общедоступные файлы GitHub по HTTPS и проверяет адрес репозитория, канал, версию, размер и SHA-256 архива. Пароль или токен GitHub сотрудникам не требуется.

Обновление кода и справочник источников — отдельные механизмы. Существующая работа источников и карт от подключения этого канала не меняется.
