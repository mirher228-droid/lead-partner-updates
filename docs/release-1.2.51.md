# Общая версия 1.2.51

Сохранены привычный интерфейс, настройки и идентификатор общей панели Авито.

- Исправлено определение КП/МНЧ/БТ по меткам профиля и услугам, включая
  смешанные русские и латинские буквы. При сравнении учитывается каталог
  нужного партнёра; ошибка CRM не выдаётся за пустой список другой базы.
- Убраны повторные чтения при открытии карточки и лишняя загрузка форм
  и расписания во время сравнения баз. Одинаковые проверки объединяются.
- Черновики и ручной выбор защищены при смене диалога, загрузке новых данных
  и поздних ответах. Черновик одного клиента не переносится другому.
- Усилено восстановление после неопределённого результата сохранения,
  чтобы не отправлять ту же заявку повторно. Недействительный контекст
  блокирует действия; после восстановления панель продолжает работу.
- Ограничен рост временных кэшей и уменьшена фоновая нагрузка скрытой вкладки.
  Исправлены гонки каталога источников и проверка повреждённых границ карты.

Изменения проверены на искусственных данных с настоящим Chromium. Живые
заявки в CRM при проверках не создавались; это не заявление о проверке
каждого рабочего компьютера.

Если автообновлятор уже установлен, пакет загрузится при очередной проверке
и применится после полного закрытия браузера. Переустановка расширения
и новые разрешения не требуются.

## Подготовка и порядок публикации

Этот документ подготовлен до выпуска. Факт публикации подтверждают успешные
Actions и итоговая проверка общедоступного канала, а не наличие этого файла.

1. Обновить только номер версии manifest до 1.2.51. Ключ и разрешения должны
   совпадать с неизменяемым архивом Common 1.2.50.
2. Сохранить чужие изменения, получить актуальный main и отправить release
   commit с исходниками, тестами и workflow `publish-common-1.2.51.yml`.
3. Публикующий workflow вызывает `cloud-common.yml` как обязательный build job
   через `workflow_call` на том же SHA. Windows выполняет Node/Chromium и
   Python-проверки, собирает ZIP и проверяет его через `Test-CommonArchive`.
   Используется единственный ZIP артефакта `common-test-build` текущего run,
   без повторной сборки на публикующем шаге.
4. Выполнить семь существующих Windows PowerShell 5.1 suites. Сверить inventory
   ZIP с checkout, версию, ключ и разрешения. Построить setup и update.json
   существующим `Publish-Release.ps1` из проверенных байтов архива.
5. Пока latest остаётся `common-v1.2.50` и тег 1.2.51 свободен, создать draft
   с тремя файлами. Скачать их обратно и сверить SHA, имена и target commit.
   Только затем опубликовать стабильный `common-v1.2.51` как latest. Старые
   архивы и выпуски не перезаписываются.
6. После освобождения блокировки публикации отдельный Ubuntu job запускает
   существующий `release-common.yml` с `--ref common-v1.2.51`. Тег закрепляет
   проверку на том же SHA независимо от последующих изменений main.
7. Дождаться именно нового workflow_dispatch-запуска на этом SHA. Проверить
   latest stable, публичный update.json, SHA/размер скачанного ZIP и содержимое
   setup по хешам файлов исходного Windows job. Не объявлять всех сотрудников
   обновлёнными до закрытия их браузеров.

Публикация останавливается при ошибке обязательного build, несовпадении
исходников/артефакта, занятом теге или неожиданной смене latest. Длительный
пятичасовой прогон предыдущего этапа относится к прежнему снимку исходников;
ему не приписывается проверка нового release commit. Подробности исправлений
и локальных замеров: `base-selection-validation.md`, `reliability-extended.md`.
